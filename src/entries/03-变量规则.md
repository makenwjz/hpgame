<变量规则>
【总则】只按本轮正文里已经发生、有因果依据的事更新；「可能发生」不写。没有变化就整块省略 <UpdateVariable>。

【MVU 语法】变量更新走 MVU，不写 JSONPatch。每次回复末尾有且只有一个 <UpdateVariable> 块，块外不写任何变量内容：

<UpdateVariable>
<Analysis>
逐项核对本轮发生了什么、对应哪些路径（没变写 N）：
主角 / 时空 / 日程 / 五维 / 关系 / 网 / 秘密 / 宫殿 / 队伍 / 能力 / 物品与金钱 / 守护神 / 主角状态 / 事件线索 / 期限
</Analysis>
_.set('时空.日期', '1991年09月01日', '1991年09月08日');//跨过一周
_.set('五维.学业.经验', 2, 3);//自习一次
</UpdateVariable>

· 路径用点号分层，**不写开头的斜杠**：/主角/体力 → 主角.体力
· 第三个参数写新值：数字写数字、文本写引号、布尔写 true/false
· 每条后面用 // 写一句原因
· 同一路径一轮只出现一次；数值一次算完再写结果

【更新时机】
· 场景切换 → 时空.日期 / 时空.时段
· 检定结束 → 主角.体力 / 主角.魔力 / 主角.伤势（脚本写，模型不写）
· 互动结束 → 模型发 <affinity>，脚本写 关系
· 主线推进 → <event>，脚本写 事件线索 与 主角.学院分
· 进入/离开宫殿 → 脚本写 宫殿
· 跨过周一 → 脚本写 时空.周 与 日程

【各容器】
· 五维：只由日程脚本加经验；每阶 6 点，满则升阶；每学年每维 ≤2 阶（12 经验）。
· 关系：Rank/社群点只由社群脚本写；模型只写档案（首次登场 16 项）。
· 网：只存变过的边，上限 60；由社群脚本按牵动规则写。
· 秘密：发现度由剧情脚本写。
· 宫殿：位置、灯火、密钥由前端写；改心与战利品由脚本写。
· 队伍：战斗脚本写，前端只显示。
· 能力：模型写 <ability>，值 0–20。
· 期限：状态由剧情脚本写。

【兜底】缺失、类型不对：正文与状态栏显示「未知」或「—」，不补造。超范围夹回范围；枚举拿到表外值按最接近项写回。
</变量规则>
