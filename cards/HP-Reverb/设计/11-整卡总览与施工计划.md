# 11 · 整卡总览与施工计划

> 这份回答三个问题：**整张卡是什么 / 需要做什么 / 我打算怎么做**。
> 冲突时以 `设计/README.md` 的优先级为准；本文件只做总账，不新增设定。

---

## 一、一页看懂

**一句话**：1991 年，全员娘化的巫师界，你是唯一的男学生哈利·波特。
白天在霍格沃茨过日子、排日程、经营关系；夜里走进别人的心里——**9 座宫殿、22 张塔罗、八方式回合战斗**。
**121 个人可攻略（三层深度）、11 个人只能被阻止。**
一年 43 周、172 个行动点、3 次涨潮。你救不了所有人，这就是全部设计。

**玩家的一局长什么样**

```
每周 4 行动点
 ├─ 陪人   → 社群点 → Rank 1–10（每级给东西）
 ├─ 自习   → 五维经验 → 1–5 阶（门槛）
 ├─ 打工/采买 → 加隆、礼物
 ├─ 休息   → 回血
 └─ 潜入   → 行间 → 宫殿（探索 + 八方战斗）→ 拿秘宝 → 改心
       ↓
   每周结算（日期 +7、期限倒计时、生日、世界事件）
       ↓
   每学年 3 次涨潮（万圣 / 圣诞 / 期末）→ 逾期不可逆
       ↓
   七学年 → 四层结局（期限清算 / 深线 / 社群 / 世界）
```

**主题**：不是「攻略所有人」，是「你只有一年、七次涨潮、一百二十一个人，你打算把谁留在门外」。

## 五、我打算怎么做（工作方法）

### 5.1 每次会话只推进一个 M

1. 先读 `进度.md` 与 `README.md`；
2. 确认这次属于哪个 M，**只改这个 M 涉及的文件**；
3. 改完写回 `进度.md`，记录「改了什么、没改什么、下次从哪继续」。

### 5.2 内容写作顺序：先骨架，后血肉

```
骨架：人设七段的六个标题 + 十级台阶的一行戏眼
  ↓
血肉：逐级扩写（每级 2–4 句）
  ↓
装饰：台词、口癖、专属物件
```

理由：22 人 × 10 级 = 220 条台阶，先写骨架才能看出「有没有重复」。

### 5.3 三条一致性检查先于内容

- `check-contract`：契约枚举 ↔ 脚本常量 ↔ 正文格式
- `check-paths`：ZOD ↔ 路径清单 ↔ 白名单 ↔ initvar
- `check-names`：人设名 ↔ 脚本名单 ↔ 学年线人物表

**这三个脚本是 v10.1 唯一没做的工程纪律**，也是这次重构最值钱的部分。

### 5.4 并行冲突的处理

现在目录里有 6 份 `06-*`、2 份 `07-*`，是不同批次的产物。我的规则：

1. **不删别人的文件**，只在 `README` 标优先级；
2. 新设定一律写进新文件，回头再合并；
3. 每次改 `00` 这种公共文件前先读一遍当前内容，不整段覆盖。

## 六、风险与取舍

| 风险 | 现实 | 处理 |
|---|---|---|
| 22 人 × 10 级写不完 | 220 条台阶 | 浅节点只给 1–5 级；核心 22 人分级（12 人写满，10 人写 7 级） |
| 前端太复杂 | 探索 + 战斗两套 canvas | 先做 ASCII 降级，像素后置；战斗先做「自动战斗 + 摘要」 |
| 模型不守契约 | v10.1 已证明 | 契约常驻 + 剥离自写标签 + 检查器 |
| 战斗拖慢聊天 | 一场 12–20 回合 | 自动战斗、跳过动画、每场只给摘要 |
| 无真机 | 静态通过 ≠ 运行通过 | 所有运行时结论标「未验证」，M7 统一收 |
| 并行写作冲突 | 已完成一次 | README 优先级 + 文件所有权 |
