## 1. 八个脚本

v10.1 是六个（其中两个因契约缺失空转）。重构后八个，每个只管一件事。

| # | 脚本 | 职责 | 监听 | 读 | 写 |
|---:|---|---|---|---|---|
| 1 | MVU | 加载内核（四源兜底） | 启动 | — | — |
| 2 | ZOD | 注册 schema + 导出 `sanitizePatch` | 启动 | — | — |
| 3 | 世界书控制器 | 开局 / 学院 / 学年三组互斥 | CHAT_CHANGED / MESSAGE_SENT / VARIABLE_UPDATE_ENDED | 开局、学院、学年 | 世界书开关 |
| 4 | 日程 | 行动点、周结算、五维经验、考试、日期 | `<act>` / MESSAGE_RECEIVED | 日程、五维、时空 | 日程、五维、时空、日期 |
| 5 | 对峙 | 掷骰、修正、结算、输出 `<check>` | `<roll>` / MESSAGE_RECEIVED / SWIPED | 五维、主角、能力、潜伏 | 体力、魔力、伤势、声望 |
| 6 | 社群 | 好感、Rank、门槛、奖励、档案、网边 | `<affinity>` / MESSAGE_RECEIVED / SWIPED | 关系、五维、网 | 关系、网 |
| 7 | 行间 | run 状态机、回声、残留、撤离、深线 | `<act do="潜入">` / MESSAGE_RECEIVED | 潜伏、行间、同行 | 潜伏、行间、体力 |
| 8 | 剧情 | `<event>`、涨潮、结局标记、学年推进 | `<event>` / MESSAGE_RECEIVED / SWIPED | 事件线索、期限 | 事件线索、期限、主角状态 |

**不变量（每个脚本开头写死）**

```
I1 不写不属于自己的容器
I2 没有请求就什么都不做
I3 写回前过 sanitizePatch（路径白名单）
I4 失败不抛死循环，出错卡 + 一次性重试
I5 所有枚举来自契约，不在脚本里另造同义词（别名表可以有，但必须收在同一处）
```

### 2.4 日程

```js
onAct(req) {
  if (本周已用 + cost > 4) return reject('这周的安排满了');
  本周已用 += cost;
  写 时段（按 slot 映射）;
  if (do === '潜入') { 潜伏.在行间 = true; 体力 -= 10; }
  if (do === '自习') 五维[target].经验 += 1（受子上限）;
  if (do === '打工') 钱 += 40~80, 对应经验 += 1;
  if (do === '休息') { 体力 += 25; 魔力 += 25; 伤势 -= 10; }
  if (本周已用 >= 4) 周结算();
}

周结算() {
  周 += 1; 日期 = 1991-09-01 + (周-1)*7;
  体力 += 10; 魔力 += 10; 伤势 -= 5;
  期限倒计时刷新;
  生日检测();
  每 3 周 → 世界事件;
  连续两周体力<20 → 强制休息;
}

升阶检查() { if (经验 >= 6) { 阶 += 1; 经验 = 0; 标记「待演出」；} }
```

**考试**：第 21 / 42 周触发，按 `01` §4.2 公式结算。

### 2.5 对峙

```js
onRoll(req) {
  const 判定线 = clamp(50 + 学派 + 熟练 + 同行 + 残留 + 五维
                       - 敌人 - 回声 - 伤势, 5, 95);
  const d = 1 + floor(random()*100);
  const 结果 = d <= 3 ? '极值成功'
             : d <= 判定线 ? '成功'
             : d <= 判定线 + 15 ? '部分成功'
             : d >= 98 ? '极值失败' : '失败';
  结算(结果);
  输出 <check type="…" actor="{{user}}" dc="…">…</check>;
}
```

**禁止**：模型直接写 `<check>` → 正则剥离 + warn。

### 2.6 社群

```js
onAffinity(req) {
  if (!PEOPLE.includes(req.name)) return warn('名单外，不结算');
  delta = clampByKind(req.kind, req.delta);      // 2/5/8/10
  delta = weeklyDecay(req.name, delta);          // 一周第二次 ×0.5
  点 += delta; 点 = clamp(0, 100);
  want = 1 + floor(点/10);
  if (want > Rank) {
    if (!gatesMet(req.name, want)) { 回执('差一点'); return; }
    Rank = want;
    if (want === 10 && !三维持4阶) { Rank = 9; 回执('还差三维'); return; }
    发奖励(want);
    触发牵动(req.name, want);   // 改 /网
    if (want === 9) 开启恋分支();
  }
}
```

### 2.7 行间

```js
状态机：门 → 重 → 部位 → 撤离
onAct(潜入) → 选门 → 生成第1重 → 等模型写
on部位结算 → 回声 += 3/8/15；意志检查；残留入包
每重结束 → 领会三选一 → 重+1
撤离 → 带出 = 到达重数；写 /行间/记录；清 /潜伏；体力 -= 10
被打出 → 带出 = floor(件数/2)；触发不可逆后果；断边/受伤/期限-1周
```

### 2.8 剧情

```js
onEvent(ev) {
  主线节点 → 写 /事件线索/主线节点进度（终态不回退）
  支线     → /关系/{名}/支线状态 只进不退 + 进行中支线
  社群     → **只记录事件名**，不改 Rank（Rank 由社群脚本写）
}
```

> 这一条是 v10.1 的教训：`剧情推进` 曾经自己算 Rank，与社群脚本打架。现在它只写「演过哪一场」。

## 5. 三个一致性检查脚本（发布前必跑）

### 5.1 `check-contract.mjs`

比对三处的枚举：

| 来源 | 提取方式 |
|---|---|
| 契约条目 | 解析 ``` 代码块里的 `xxx : a \| b \| c` |
| 脚本 | 提取 `CHECK_TYPES` / `TRIGGERS` / `NODE_STATES` 等常量 |
| 正文格式 | 提取 `<check type="…">` 的说明文本 |

**任一不一致 → 退出码 1**。v10.1 的「13 类实现 6 类」就是这里漏掉的。

### 5.2 `check-paths.mjs`

比对各处路径集合：ZOD schema ↔ 路径清单 ↔ 白名单 ↔ initvar。
**多一个或少一个都算失败**。

### 5.3 `check-names.mjs`

比对各处人名：人设规范名 ↔ 脚本 PEOPLE ↔ 学年线人物表 ↔ 支线「关联支线」。
**变体（鲁贝娅/鲁贝拉）算失败**。
